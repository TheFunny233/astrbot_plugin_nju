# NJU小工具管理bot

轻量 AstrBot 插件，接收 APP / Web 的签到及场馆预约结果，只发送到每条通道明确绑定的群聊和私聊。同一个 Bot 可创建多个 API，各自独立控制接收范围。

## 快速接入

1. 在 AstrBot 通过本仓库地址安装。需要 AstrBot 4.29.4 或更新版本，使用插件可视化视图和 `astrbot.api.web`。
2. 插件配置填写 `public_base_url`，例如 `https://bot.example.com`。通知监听默认 `0.0.0.0:9285`，可修改 `listen_host` / `listen_port`。Docker 需要映射此端口；反向代理到该端口。
3. 在 AstrBot 消息平台中配置需要使用的机器人，支持列出所有已配置协议，不限 OneBot。
4. 在要接收通知的群里 @机器人发送一条消息，或让接收人私聊机器人一次。插件会自动记录目标，不需要填写 OpenID，也不需要发送获取标识的指令。
5. 在插件详情 →「通知通道」点击「刷新列表」，新建通道、选择发送机器人，勾选已记录的群聊和私聊用户。可搜索群名、昵称或备注；群聊和私聊可同时选择，只有一个机器人时自动选择。QQ 官方未返回名称时，可点击「备注」设置易于辨认的名称。
6. 保存后点击「复制 API」。签到通道填入签到 APP / Web 的 Bot 通知设置；抢场通道填入 [NJUGymsReservationHelper](https://github.com/TheFunny233/NJUGymsReservationHelper) → 设置 → AstrBot。开启并保存后，可由用户点击测试通知。

插件从收到的消息自动取得对应平台的路由标识，QQ 官方 OpenID 等由插件保存。记录目标只增加可选项，不会自动建立通道或订阅通知。不会自动枚举或广播到所有群聊。机器人需要拥有目标的发送权限，平台必须支持主动发送；接口返回 accepted 只表示入队，具体失败可在管理页查看。

## 本次更新（v2.4.0）

抢场模块已正式实现，接收预约成功、待确认、失败及错过执行时间等结果。预约助手统一在设置页配置通道，通知队列和事件去重独立于预约任务；重试通知不会再次预约。现有签到通道及 API 保持兼容。

## 配置与数据文件

仓库内的 `_conf_schema.json` 仅为配置字段和默认值，不包含运行中的 Bot 配置。机器人登录信息、完整通道 API、通道凭证、接收群聊/私聊记录和 SQLite 队列均不随源码发布。

插件运行数据保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_nju/`。`.gitignore` 同时排除了本地数据目录、数据库、密钥、`.env`、备份和打包输出；请在 AstrBot Dashboard 中配置实际地址和接收目标，不要将它们写进源码或提交到 GitHub。

## 通道管理

- 支持创建、编辑、启用/关闭、删除和重置 API。最多 100 个通道，每通道最多 30 个接收会话。
- 每个通道有独立的 256 位随机凭证。修改接收范围不改变 API；重置 API 立即撤销旧凭证；删除通道会取消尚未发送的通知。
- 关闭通道拒绝新通知，暂停队列；重新开启后继续发送。移除的接收会话不会继续收到尚未发送的通知；已经进入平台发送过程的消息无法撤回。
- 地址含发送凭证，不能公开分享。外网部署使用 HTTPS，并在反向代理上关闭通知路径的访问日志或遮蔽凭证路径；插件自身不记录该路径。
- 管理接口走 AstrBot Dashboard 的登录鉴权；外部通知端口只提供 POST 上报，不提供管理接口。

## 三个独立业务模块

| 业务 | 接口 | 当前状态 |
| --- | --- | --- |
| 签到 | `/api/v1/checkin/<channel>/<token>` | 已实现 |
| 抢课 | `/api/v1/course/<channel>/<token>` | 预留，默认关闭，启用后返回 501 |
| 抢场 | `/api/v1/venue/<channel>/<token>` | 已实现，支持预约成功、待确认、失败和测试通知 |

模块分别导入，具有独立发送工作协程和每模块 3000 条队列上限；一个模块导入/格式化失败、超时或积压不影响其他模块。每个目标独立投递、最多尝试三次，8 秒超时，10/20 秒重试间隔；单个群聊失败不会阻断其他群聊或私聊。

队列和去重记录使用 SQLite 保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_nju/notifications.sqlite`，重载/重启恢复。保留七天，每小时按需清理。相同通道、相同 event_id 七天内只入队一次；失败目标不会导致已成功的目标在普通重试时重复发送。平台已接收但本地未收到确认时仍可能重复，无法承诺端到端恰好一次。

这是同进程内的业务故障隔离；AstrBot 整体停止、磁盘损坏、进程崩溃或恶意阻塞事件循环会影响整个插件。插件不运行签到或抢课抢场脚本，也不接受任意系统命令。

## 接口约定 v1

复制出来的完整地址示例：`https://bot.example.com/api/v1/checkin/<channel>/<token>`。

`POST`，`Content-Type: application/json`，请求体上限 256 KiB：

```json
{
  "version": 1,
  "event_id": "client-generated-unique-id",
  "source": "app",
  "activity_name": "高等数学",
  "finished_at": "2026-11-12T12:00:00Z",
  "results": [{"name": "同学甲", "ok": true}, {"name": "同学乙", "ok": false}]
}
```

测试通知使用 `{ "version": 1, "event_id": "unique-test-id", "test": true }`。

- 202：持久化入队，`accepted: true`。
- 200：重复事件，`duplicate: true`，不重复入队。
- 400：输入格式不正确；401：地址凭证无效/撤销；403：通道关闭。
- 429：当前业务积压，请稍后用相同 event_id 重试；501：预留业务；503：模块不可用。

仅展示明确字段，不把上报内容作为指令、富文本或模型提示执行。姓名和消息长度受限，最多列出 30 人，优先失败人员；不发送密码、Cookie、学号、位置、原始签到链接或原始错误正文。

## 验证与发布

```sh
python -m unittest discover -s tests -v
python -m compileall -q main.py service.py targets.py discovery.py modules
```

业务与队列测试不依赖 AstrBot；实际 QQ 送达还需要安装插件后配置适配器，并在目标会话执行连接测试。本插件不会替用户安装或配置 QQ 机器人平台。

## 2.1 升级兼容

旧通道、凭证、通知地址、待发送队列保持不变。单个机器人下的旧数字会话会自动显示为群号和 QQ 号；跨机器人等特殊旧通道可继续启停、复制 API 和保留原接收范围。更换接收范围可新建通道。旧管理请求中的 `targets` 字段继续兼容。

2.1 的通道保存参数 `platform_id`、`group_ids` 和 `user_ids` 继续兼容。每个通道最多 30 个接收目标。`/nju会话` 仅作为旧版兼容和排查指令保留，正常配置不需要使用。

## 2.2 多协议支持

列表显示所有已配置的机器人，包括 QQ 官方、OneBot、Telegram、Discord、Satori 以及第三方适配器，不再按 OneBot 白名单过滤。接收目标始终通过 AstrBot 对应平台的 `send_by_session` 路由，不绕过平台权限。

- OneBot：群号、QQ 号，保留数字校验。
- QQ 官方：群组 OpenID、用户 OpenID。标准 32 位十六进制群组 OpenID 通过适配器的公开场景登记方法识别为群聊，不会混入频道路由；官方权限、消息交互状态和配额仍然适用。
- Telegram：支持负数群聊 Chat ID。
- 其他协议：支持适配器使用的字符串目标 ID（如频道、Matrix room ID、私聊会话 ID 等）。

读取适配器声明的主动发送能力，同时识别尚未实现实际发送方法的适配器。明确不支持主动通知的连接只能保存关闭的通道；未运行的连接允许先保存配置，发送时重新检查。一个适配器状态读取异常不会隐藏其他连接。

“列出全部协议”不代表所有平台都允许主动消息。平台不提供主动推送、目标无权限、官方额度不足等情况仍可能无法发送。旧通道、API 凭证与通知地址保持不变。

## 2.3 自动记录接收目标

收到群内 @机器人消息或私聊消息后，自动保存平台、投递目标、可用名称和最近互动时间。群内普通消息、@其他人以及机器人自身的消息不会加入列表，群成员也不会因此成为私聊候选人。记录不回复消息、不停止其他指令处理；单次记录失败不影响通知工作协程。

记录和备注保存在同一个 SQLite 数据库的 `recipients` 表中，插件重载或 AstrBot 重启后保留。只保存路由标识、名称、备注和时间，不保存聊天内容或原始事件。群聊隔离会话中的成员前缀会在标准 `成员ID_群ID` 形式下去除，同群多个成员 @不会产生多个接收项。平台没有提供名称时，页面显示标识末尾以区分，并允许添加备注。

管理页改为勾选群聊和用户，支持搜索、刷新时保留未保存的选择，以及每个机器人独立的目标列表。新保存请求使用 `platform_id` 和 `recipient_targets`，后者只能选择该机器人已经记录或已有通道正在使用的目标。旧通道即使尚未再次互动，仍可以保留和编辑，凭证、通知地址和队列不变。

插件只能记录 AstrBot 实际交给插件处理的消息。机器人应在线，NJU 插件应在对应会话启用，相关白名单和平台权限仍然生效。升级前的聊天不会自动回溯，升级后互动一次即可记录。


## 2.4 场馆预约助手接入

1. 升级插件后，在“通知通道”新建业务为“抢场”的通道，选择机器人及接收群聊/私聊，并启用通道。
2. 复制该通道生成的 `/api/v1/venue/<channel>/<token>` 完整地址。
3. 在 NJUGymsReservationHelper → 设置 → AstrBot 通知中粘贴地址，开启并保存。
4. 可点击预约助手的测试按钮；API 返回 accepted 表示进入插件的持久化发送队列，实际送达状态在插件通道页查看。

抢场事件沿用 v1 接口和独立队列。相同 event_id 重试不会重复入队；通知重试不会触发重新预约。已有签到通道、凭证、队列和 API 保持兼容，抢课模块仍为独立预留模块。

```json
{
  "version": 1,
  "event_id": "venue-task-id-run-time",
  "source": "gyms",
  "status": "unpaid",
  "finished_at": "2026-11-14T08:00:08+08:00",
  "reservation": {
    "venue_name": "苏州校区室外场地",
    "site_name": "网球场",
    "date": "2026-11-14",
    "start_time": "19:00",
    "end_time": "20:00",
    "space_name": "西区1号"
  }
}
```

status 支持 paid、unpaid、failed、unknown、missed。unknown 会明确提示去学校核对、勿重复提交。仅转发场馆、项目、日期、时段、场地及受控状态文案，不发送学号、密码、Cookie、访问令牌、同伴资料或学校原始错误正文。测试事件使用 version、event_id、test=true。
